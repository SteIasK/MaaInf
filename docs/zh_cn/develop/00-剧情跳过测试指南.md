# 剧情跳过 · 首次测试指南

> 坐标系：所有 roi/坐标基于 `display_short_side: 800`（2560x1600 → 1280x800）。
> 模板图由截图按 50% 缩放裁剪，与运行时截图同尺度。

## 测试前检查

1. 游戏显示模式 = 全屏(无边框) 或 窗口（不要独占全屏）
2. 游戏窗口不最小化
3. VSCode 已装 `MaaFramework Support` 插件（nekosu.maa-support）

## 测试步骤

1. **连接测试**：VSCode 打开项目 → 插件面板选择"桌面端"控制器 → 从窗口列表选择游戏窗口 → 执行任务「连接测试」→ 手动截图，确认截图内容正常（非黑屏）且尺寸为 1280x800。
   - 黑屏：把 `interface.json` 里 `screencap` 改为 `DXGI_DesktopDup` 再试，仍不行换 `GDI`。
2. **单节点验证**（用插件对单个节点"点击执行"）：
   - 站在剧情树界面 → 跑 `剧情树_最新未读`：应看到右上角按钮被点击。
   - 在对话界面 → 跑 `剧情_快进按钮` / `剧情_对话推进`。
   - 音游配置界面 → 跑 `音游_静默等待`：应识别命中并停住等待。
3. **整体流程**：站在剧情树 → 执行任务「剧情跳过」→ 观察完整链路：
   `最新未读 → 开始 → 对话推进 → 快进 → OK确认 → (不可跳过段持续点击) → 音游配置(静默) → 手动打完 → 结算点击 → 回到剧情树 → 自动下一章`

## 需要重点观察的 4 个问题（测试后反馈）

1. **快进按钮是否被反复点击**：如果它是"开关"，重复点击会把快进关掉——需要改成单次触发模式。
2. **对话画面是否点一下就能推进**：`剧情_对话推进` 点击的是画面中央 (640,400)。
3. **音游结束是否还有别的结算页**（除"配方已获取"外）：有的话截图给我加节点，否则脚本会在那个界面静默卡住直到超时。
4. **剧情全部读完后的表现**：脚本应停在剧情树界面 120 秒后自动结束。

## 运行方式与紧急停止（重要）

**方式 A：命令行运行器（推荐，带急停热键）**

```bash
pip install -r requirements.txt   # 首次: MaaFw + keyboard
python runner.py --dry            # 排查连接: 只截图不点击, 输出分辨率和亮度
python runner.py                  # 运行剧情跳过, 3 秒后生效
```

- **F10 = 紧急停止**（全局热键，游戏内也生效）；或在控制台按 Ctrl+C
- 启动后有 3 秒缓冲期，请切到游戏窗口

**方式 B：VSCode 插件运行**：插件面板上有停止按钮，任务卡死时先按停止再关窗口。

  ② 游戏引擎忽略 SendInput 合成输入。

## 窗口模式与多分辨率

- **架构天然支持窗口模式**: 截图(FramePool)、点击换算(实时客户区+ClientToScreen)、
  前台守卫都与窗口模式兼容。
- **几何要求**: 内容区必须以 1280x720 渲染才与模板匹配。两种达标方式:
  1. **窗口模式(推荐, 通用)**: `python -u runner.py --fit1280`
     自动把游戏窗口客户区标准化为 1280x800 (16:10), 画面几何与 16:10 全屏
     完全一致 —— **一套模板通吃, 测试者显示器分辨率无所谓**(装得下窗口即可)。
  2. **16:10 全屏**: 2560x1600 等原生分辨率直接跑, 现有配置即为此标定。
- 16:9 显示器全屏(1080p/1440p)暂不支持(内容渲染 11% 放大, 模板失配),
  这类用户请用窗口模式; 未来出 720 短边资源变体后可支持。
- 运行中**不要拖动/缩放窗口**: 尺寸变化会被检测并警告, 识别会失效。
- 脚本运行中窗口置顶归脚本管, F10 停止后一切归还。

## 分辨率自适应（已实现）

runner 启动时按游戏窗口客户区尺寸自动计算: 截图短边 + 内容区(恒为 1280x720)偏移,
并通过 pipeline_override 平移所有 roi —— **任意分辨率/比例全屏或窗口均自动适配,
模板单套通用**。已验证的换算:

| 场景 | 截图短边 | 内容偏移 |
|---|---|---|
| 16:10 全屏 (2560x1600) | 800 | (0, 40) |
| 16:9 全屏 (1920x1080 / 2560x1440) | 720 | (0, 0) |
| 窗口 1280x800 客户区 | 800 | (0, 40) |
| 窗口 1600x900 客户区 | 720 | (0, 0) |
| 4:3 / 带鱼屏 (极端) | 自动 | 自动居中 |

规则: 短边 = 1280 x 客户高/客户宽; 偏移 = 截图与内容区差值的一半。
带负数的 roi 会自动钳制到边界。

## 复现标准流程（剧情树 → 跳过一章）

1. 游戏停在剧情树界面
2. `python -u runner.py`（**-u 必须带**，否则日志缓冲看不到实时输出）
3. 3 秒后切到游戏，之后不干预
4. 正常表现：自动 最新未读→开始→对话→快进→OK→不可跳过段持续点中心
   → 配装界面出现后**控制台安静下来 = 静默生效**，安心打歌
5. 打完 → 结算页自动点击 → 回剧情树自动开下一章
6. 中途停住：**不要动游戏画面**，保留现场，说一声"停了"——
   读 `debug/debug/maafw.log` 尾部的识别得分 + 截屏即可定位缺哪个节点

## 打包分发（已实现）

- 形态: **便携文件夹 zip**（MaaInfPortable.zip, 约 93MB, 解压后 208MB）
- 构成: 嵌入式 Python 3.12.10 + MaaFw(numpy/onnxruntime/DirectML/OpenCV 原生库)
  + Pillow/keyboard + runner.py + agent/ + assets/（含 OCR 模型 30MB）
- 构建: `build/` 下的 python-embed.zip + get-pip.py → 组装脚本见 dist/MaaInfPortable 结构;
  依赖安装走清华镜像。启动器为 MaaInf.bat（透传参数, 支持 --dry/--fit1280/任务名）。
- **单文件 exe 不可行**: PyInstaller 打包 (48MB) 在 maa 原生 DLL 家族上触发
  DllMain 1114, 二分排查 api-ms/UCRT/VC 运行库组合均无法根治
  （新版 Windows 的 API 集合解析 + 私有运行库冲突）。MAA 官方同样采用
  文件夹分发 + 依赖库安装 bat, 不提供单文件。
- 用户机器要求: Win10/11 x64; 若提示缺 VCRUNTIME140/MSVCP140 → 装 VC++ Redist。
- 使用说明.txt 已随包分发。
